# ARM64命令語辞書 — fieldlang-asm V1自宿準備 (2026-08-01, narigo)

対象: packages/fieldlang-asm/{lexer,emit,driver}.s 実使用mnemonicのみ。
照合法: `as -arch arm64` → `objdump -d` → hex32抽出。印: 真=objdump照合済 · 未驗=手組bit未照合。
全例=LE u32。bit図: [31..0]。

## 0. 使用mnemonic目録 (出現数, 三.s合算)

## 2. Mach-O arm64 最小実行像 (V1: linker棄用)

方針: 固定layout、全offset compile時定数。数百byte header + __TEXT一発書出し。

```
offset 0    mach_header_64 (32B)
  magic=0xFEEDFACF · cputype=0x0100000C(ARM64) · cpusubtype=0
  filetype=2(MH_EXECUTE) · ncmds/sizeofcmds=下記合算 · flags=MH_NOUNDEFS|MH_PIE(0x200001)
offset 32   LC_SEGMENT_64 "__PAGEZERO" (72B, nsects=0)
  vmaddr=0 vmsize=0x100000000 fileoff=0 filesize=0 prot=0/0
offset 104  LC_SEGMENT_64 "__TEXT" (72+80=152B, nsects=1)
  vmaddr=0x100000000 vmsize=0x4000 fileoff=0 filesize=全file長 prot=5/5
  section_64 "__text": addr=0x100000000+code_off · offset=code_off · align=2
offset 256  LC_UNIXTHREAD (0x5) 或 LC_MAIN(0x80000028)
  LC_UNIXTHREAD: cmd+size+flavor(ARM_THREAD_STATE64=6)+count(68)+regs[34×u64] = 288B
    pc=entry vmaddr、他reg=0 — dyld不要、静的専用
  LC_MAIN: 24B {cmd,size,entryoff u64,stacksize u64} — 但しdyld前提(LC_LOAD_DYLINKER要)
→ V1択: LC_UNIXTHREAD(dyld回避、syscall直)。 未驗: 現行macOSでdyld無し静的実行はcodesign(ad-hoc)+適切なsegment整列要 — 実機起動テストで真化すべし。
code_off: header合計を0x4000(page)整列が安全側。
syscall: svc #0x80 · exit=0x2000001 · read=0x2000003 · write=0x2000004 (driver.s現行と同一番号系)
```

未驗: 上記offset/size数値は記憶起こし。V1実装時 `otool -l` で既存fieldc実行像と照合し真化。

## 3. Emit層分離設計註

現状評 (emit.s):
- 良: token走査/引数取得(Lget_u32/Lget_int)/直列化(Lput_u32, strb tag)が既にleaf化 — 境界萌芽有
- 難: tag別dispatch(Ltag3/Ltag1/Ltag_one/Lvar)内でget/putが交互直結 — 「意味検査」と「byte書出」が同一枝

分離線提案 (V1移行、lexer/parser不変):
```
層A 意味層: token→(op, args[], arity, arg幅) 正規化record — 現dispatch表をdata化
  表: {kind, arity種別(fix3|slot+u64|one|var), 検査(u32範囲)}
層B 序列化層: record→bytes — 現FLDJ書式 (V0互換)
層B' 代替序列化: record→ARM64機械語 — §1辞書表がそのままdata表に
```
- V1=層B差替のみ: 層Aのrecord列は不変 → lexer.s/driver.s無改変
- §1の各encode類=「基底word | fieldマスク | operand挿入位置」の3組表 → emit表=data、命令追加=表1行
- Lput_u32相当がbyte sink抽象: bounds+cursorは共通のまま
